# LoadFile cache-hit evidence — 2026-10-19

This checkpoint covers a conditional, bounded cache-hit path. It does not load record files or manufacture a fallback table. The original target is the read-only `D:/Steam/steamapps/common/Grim Dawn/x64/Engine.dll`, SHA256 `4c2ea14ce1c591b315cc29a8a96819a5c3c7e194adbd6f7eea208b9bb8a93153`. Rea 6.5.0 / Ghidra 12.1.4 produced the retained pseudocode, assembly and resolved-callee evidence. Decompiled types and names are analytical aids; instruction operands determine the rules below.

## Name processing and explicit locale boundary

The [name-processing assembly](rea-record-load-dependencies/05-LoadFile-name-processing-0x18027b3c0-assembly.json) for `0x18027B3C0` iterates the full stored length, including embedded NUL, with a 32-bit increment zero-extended into the comparison. Capacity below 16 selects inline bytes; otherwise the stored pointer is used. At `27B3F7` a byte equal to `0x5C` branches to a direct `0x2F` store at `27B443`. Every other byte is sign-extended by `MOVSX ECX` and passed to IAT `0x180302BC8` at `27B418` or `27B42A`; AL replaces that byte. Length and capacity are unchanged.

[Fixed normal-import metadata](record-load-discovery/tolower-import.json), produced by the [read-only PE script](record-load-discovery/inspect_tolower_import.mjs), binds that IAT slot to `api-ms-win-crt-string-l1-1-0.dll!tolower`. It proves on-disk import identity, not the live CRT implementation or locale. Microsoft's [tolower documentation](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/tolower-tolower-towlower-tolower-l-towlower-l?view=msvc-170) and [conversion-routine documentation](https://learn.microsoft.com/en-us/cpp/c-runtime-library/to-functions?view=msvc-170) establish that `tolower` uses the current LC_CTYPE setting and leaves non-convertible characters unchanged. These are external routine contracts, not evidence that this game always uses the C locale.

`RecordLoadFile.Apply` requires an explicit `RecordNameLocale.KnownC` precondition for any byte taking the CRT branch. Within ASCII bytes 0..127, C-locale uppercase A..Z converts to a..z; other bytes remain unchanged. No host culture, Unicode decoding, path resolution or slash collapsing is used. All high-bit input bytes, including FF, are outside this implementation's normalizer coverage. An empty name or a name consisting exclusively of backslashes needs no locale, because it never reaches the import. Unknown locale otherwise stops with Unsupported before lookup. Coverage rejection is an own-model boundary, not a prediction of native invalid-argument effects or partial conversion.

## Stable cache lookup

[Lookup assembly](rea-record-load-dependencies/08-LoadFile-lookup-0x18003c8e0-assembly.json) for `0x18003C8E0` receives container, output-node pointer and full string. At `03C913..03C93F`, it applies FNV1a64 with offset `CBF29CE484222325`, prime `100000001B3`, **unsigned** byte loads (`MOVZX`) and modular multiplication over the full length. This differs from the signed-byte FNV32 raw object-name key.

The hash is masked by container `+0x30`. Bucket endpoints are at the array from `+0x18`, 16 bytes per bucket; sentinel is container `+8`. Traversal starts at bucket.first, follows node.next, and stops at bucket.last.next; an empty bucket uses the sentinel. That endpoint may be another bucket's first node, not the global sentinel. Each candidate's string starts at node `+0x10`, length `+0x20`, capacity `+0x28`. The caller's table value is node `+0x30`.

At `03C9C0`, the shorter length is compared by `0x1802EE060`; a match also requires equal lengths. The first matching candidate undergoes the opposite-direction comparison at `03CA0A` and another equal-length check. Under complete stable readable storage and the normal comparison contract, both are equivalent to full byte equality; their call count, memory access width, invalid-pointer faults and concurrent mutation are not modeled. The cache keys are already stored bytes and are **not normalized again**. Duplicate equal keys retain traversal priority; there is no invented dictionary overwrite rule.

The follow-up [comparison-entry assembly](rea-record-cache-compare/05-Record-cache-compare-0x1802ee060-assembly.json) is only `JMP qword ptr [0x180302710]`. Its decompiler output labels `memcmp` but warns that the indirect jump could not be recovered; the empty resolved-callee list is not proof of an implemented leaf body. [Static normal-import metadata](record-load-discovery/memcmp-import.json), obtained by the [fixed IAT inspector](record-load-discovery/inspect_memcmp_import.mjs), independently binds the slot to `VCRUNTIME140.dll!memcmp`. The model relies on the normal readable-buffer contract documented by [Microsoft memcmp](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/memcmp-wmemcmp?view=msvc-170): zero means the compared byte ranges are identical. It does not claim restoration or execution of the installed CRT implementation.

`RecordCacheSnapshot` represents a complete immutable own list order, bucket count and contiguous bucket segments. It preserves entry identity and table identity. The provided logical snapshot must satisfy `native mask = bucketCount-1` and correct first/last endpoints for those segments; deriving these from the constructor input does not establish a real cache's initialization. Buckets must be a power of two from 1 through 4096, entries at most 4096, each key at most 65536 bytes and total key payload at most 1 MiB. These are own coverage limits, not native restrictions. Constructors reject malformed or over-budget snapshots; this does not attempt to detect or repair native memory. Native insertion, cache ownership and cache construction remain outside this model.

## Wrapper and cache-hit effects

The earlier [LoadFile wrapper assembly](rea-object-base/11-TableDepot-LoadFile-0x1801c4d20-assembly.json) at `0x1801C4D20` locks the critical-section pointer at depot `+0x78`, initializes a local string with capacity 15 and copies the full requested name through `023180(position=0,count=UINT64_MAX)`. The normal successful assignment and growth domain was established in [name evidence](OBJECT-NAME-EVIDENCE.md). A fresh local string requires capacity 15 for length <=15, otherwise `length|15`, for covered lengths <=65536. The source's capacity is not copied. The local string is processed, then looked up in depot+8.

On a non-sentinel result the wrapper first increments the DWORD hit counter at depot `+0x54` (`1C4DB9`), then loads node `+0x30` (`1C4DBC`). Counter increment wraps modulo 2^32. A known null table stored in a real node is still a cache hit and increments the counter; a miss is distinguished by the sentinel, not payload nullness. The own snapshot requires each node and payload value to be explicitly known; null is an explicit value, not unknown metadata.

Afterward the native local heap storage is released when capacity >=16, local metadata is reset, and the wrapper unlocks before returning. Own code preserves the logical returned identity and hit effect, under normal native allocation/copy/release success. Its Monitor and managed local snapshot are not native ABI, heap, lock identity or allocation behavior. The own `finally` releases its gate even on Unsupported/managed exceptions; that cleanup is not a recovered native exception or rollback guarantee. Requests and caller-owned name strings remain unchanged.

## Miss is a real unresolved loading branch

The complete [miss assembly](rea-record-load-dependencies/11-LoadFile-miss-0x1801c4e20-assembly.json) at `0x1801C4E20` narrows the next work substantially:

1. Read timing state and obtain `gEngine+0x3D0`, used as a DatabaseArchive. Nonempty names are looked up through the same `03C8E0` at archive+0x88; node+0x30 supplies a uint record ID, with FFFFFFFF treated as unavailable.
2. Depending on archive flag byte+0x2E bit 0, obtain data through `0x180280E20`, or through the archive's uint-key index and entry offset/size at +0x28/+0x2C relative to the archive data base. This archive state and data layout are not yet reconstructed end to end.
3. A nonnull data pointer leads to allocation of 0xD0 bytes, `LoadTableBinary` construction at `0x18013F300`, and its virtual slot +8 call on a temporary data-reader structure. The conditional buffer release is also visible. The constructor and parser body are not implemented here.
4. Empty/missing/unavailable data increments depot+0x58, invokes engine diagnostic slot+0x18, allocates 0x30 bytes and constructs `LoadTable` at `0x18013C1D0`. Thus missing data does **not** simply mean returning null on normal allocation success.
5. Both branches copy the normalized name, create/cache a node via `0x18005DEB0` and `0x18002E770`, increment depot+0x50, and update elapsed/max-time counters at +0x5C/+0x60. These operations and ownership are not replaced with no-op stubs.

The own wrapper stops at the reached cache-miss boundary with `UnimplementedRecordCacheMissLoader`, before claiming any of those native effects. It does not increment the hit counter, create a fallback table, fill a cache or return Known with a fabricated null. Complete record decoding and the concrete table's Class getter remain separate gaps. Object-derived Read is a different virtual call from the LoadTableBinary parser and remains unimplemented.
