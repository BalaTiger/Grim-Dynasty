# 物品条件与统一离线规则内核

本批恢复HasItem v0/v1的限定查询链、事件16/17、开始/结束/重置钩子，并接入已有自动任务模块。`src/task_items/build_items.ps1`可重编译自有`GrimDynasty.TaskItems.dll`。统一入口为`tools/build_offline.ps1`，按依赖顺序构建九个自有DLL和四个原创场景，输出`.tooling/offline-system/`；构建/场景不需要原版DLL、原版资源、Steam、存档或新SDK。CLI参数接入工具仅在显式给出授权资源路径时读原版资源。

## 物品查询的实际范围

实际工厂case9的primary vtable为0x180796870，两个事件子对象表为0x180796858。静态来源继续复用已保存的Ghidra项目，`-noanalysis`导出，每次只处理选定入口，没有重复全库分析或运行原版。证据位于`../task-kills/ghidra-selected/item-*.json`，属于直接Ghidra静态结果，不冒称Rea成功返回。

| 入口 | 地址/已证实行为 |
|---|---|
| Read | 0x180470220，读DBR字符串与目标数量，只有version==1才读末尾布尔；v0构造默认true |
| Evaluate | 0x1804702b0，解析主玩家，调用主vtable+0x5f0，计数/目标作有符号32位六比较；布尔是查询标志，不能当成expectedHas反转 |
| Player.GetItemCountInStashes | 0x1803e4360，当前调用者为主玩家时汇总角色库存、材料表、个人箱、共享箱 |
| Character.GetItemCount | 0x180063aa0，在HasItem固定调用标志下只查Inventory，跳过直接EquipManager计数；把+0x16c0控制器ID传给库存过滤 |
| Inventory.GetItemCount | 0x18031f4b0，解析Item对象，检查完整标志、记录名，过滤控制器认定已装备的对象，再检查两个限定字符串与数量 |
| InventorySack.GetItemCount | 0x1803229d0，相同记录/完整/限定字符串查询，且没有角色控制器装备过滤 |
| GetReagentItemCount | 0x1802e29c0，材料表键为全长精确字符串，独立查Item数量；不套用背包完整/限定字符串过滤 |
| GetTransferItemCount | 0x1802d7d80，汇总非空共享箱指针，空指针跳过 |
| 记录匹配helper | 0x180593650，长度相同才逐字节CRT小写比较，并把斜杠/反斜杠视为等价 |
| 材料键比较 | 0x180019e40/0x180078960，全长memcmp/长度，区分大小写与斜杠 |
| Start/End | 0x180470720/0x180470770，分别绑定/注册两个独立处理器身份16和17，结束逐个注销与清owner |
| Reset | 0x180015880，空函数；不清变化字节，也不删除物品 |
| 事件处理 | 0x1804708d0，事件+4玩家ID必须等于客户端玩家ID，+8对象必须是Item；Object.GetObjectName与配置用_stricmp比较，命中只设置+0x14/+0x15 |
| 本地化/显示 | 0x1804704d0/0x1804707d0，仍限时间门未打开的无显示分支 |

计数循环保留32位回绕，不达到阈值后提前退出。HasItem使用的空限定向量只接受返回数据中两个限定字符串为空的物品。计数的记录匹配折叠大小写/斜杠且保留全长NUL；事件匹配是C字符串比较，会在NUL处结束，**不折叠斜杠**。材料表的键又是另一种全长精确规则。没有把三种规则统一成猜测的名称归一化。

所有容器、对象RTTI、虚表getter结果、装备位置、主玩家身份和客户端ID均来自显式模拟快照。`Slot590`结构字段、`Slot3F8`完整字节、`Slot618`数量等作为只读getter契约输入，**不等于已恢复Item生成/堆叠/制作或原版对象二进制布局**。只实现HasItem固定标志组合的计数，不宣称一般GetItemCount的所有变体/ID输出向量均已实现。ASCII CRT映射需明确上下文，非ASCII路径映射Unsupported。未知索引或必要字段不会冒充空容器。

## 自动链与真实库存边界

原创军粮场景：Start注册两处理器→Update未满足→显式声明库存快照数量变化→分派解码事件16/17→Update重新汇总并自动完成空动作任务→两处理器注销→Reset保留现有物品数量。**声明库存变化不是恢复了GiveItem/拾取/掉落动作**；没有读取或修改任何真实背包、个人箱、共享箱或存档。

提示时间门打开、非空完成动作/奖励、未知订阅或网络发送仍Unsupported。现有自动模块保留了完成历史、奖励历史字节与dirty清理/原生返回标志的顺序语义；具体奖励发放和可见UI仍未覆盖。条件达到目标不等于整个官方任务已经可玩。

## 解码器旧格式修复

原生Read证明v0没有末尾bool，既有Python/C#解码器此前会多读一字节。两个实现均已按版本修复并保留精确旧内容备份。独立手写线格式在HasItem后紧接IsDifficulty，验证v0、v1 false、v1 true三个对齐案例；完整247份现有官方任务结构与两实现仍一致，数据哈希不变。v0的默认true在条件构造语义中提供，不伪装成文件中存在的字段。

## 验收与整体覆盖

- 本模块39条计数/条件固定断言、11条自动链断言通过，覆盖四来源、装备过滤、材料键差异、完整标志、限定字符串、未知数据、双订阅、v0默认、回绕与Reset无库存删除。

- 统一九模块构建通过，436条既有/新增固定断言和四个独立原创场景都通过；统一目录DLL依赖检查无Game.dll、Engine.dll或Steam接口。原版动态参考仍未运行。

详见acceptance.json、catalog-results.json、auto-catalog-results.json、v0-wire-acceptance.json、quest-decoder-regression.json及统一输出manifest.json。源码与证据分开，历史阶段验收记录保留旧版本哈希；本批清单记录当前升级后的完整依赖。

## 下一缺口

当前内核能处理声明的事件/对象/库存输入并推进受限任务状态。尚缺实际战斗/掉落事件生产、可见提示、非空任务动作和奖励、地图/实体驱动、一般库存写入，以及原存档机制/全引擎等价证明。这些不能用模拟夹具替代。下一优先沿事件0x2a/0x2e和Complete(true)的动作/奖励链静态恢复；未证明必须运行原版才能继续。

没有原版执行、原安装/Steam/系统设置修改、真实或云存档访问，无安装、重启、提交、推送或发布。直接Ghidra初次运行产生工具用户符号缓存的事实已在task-kills审计记录；后续缓存已按进程隔离在工程内。
