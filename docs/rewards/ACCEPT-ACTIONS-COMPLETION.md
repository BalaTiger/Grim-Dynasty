# 非空任务接受事件：可用性推进

任务接受不再仅支持空事件。`AutomaticTasks.Start`现在可通过审计的AcceptActions适配器，执行从QST2定义解码的教程解锁（动作27 v0）和钱币发放（动作4 v0），然后写活动状态并注册目标。已经接通“接受时领行粮与军令教程→执行击杀目标→自动完成领取剩余军饷”的独立原创流程。

## 实际场景

`AcceptQuestDemo.exe`在内存生成原创QST2 v9任务定义，调用已有解码器和新的接受事件适配器；此定义只提供接受事件，已有原创击杀目标由运行时显式绑定，并未声称恢复整个任意QST运行时。

- 钱包初始50，奖励UID列表初始[99]。
- 首次接受：任务标志4先解锁页55，动作27再解锁页7，动作4发25钱币；钱包75，教程顺序[55,7]，UID列表[99,1]，击杀目标注册。
- 两次原创击杀事件后：自动完成，再发75钱币；钱包150，任务状态3，目标回调注销，UID列表[99,1,1]。

[直接UTF-8场景输出](accept-actions-scene.json)保存实际进程输出。原构建日志在[accept-actions-build-output.txt](accept-actions-build-output.txt)，PowerShell管道对部分中文使用了旧代码页，故原日志保持原样，场景另用原始字节捕获；ASCII验证结果与完成行完整。最终统一构建749条断言、11个场景通过，仍为10个自有DLL。新增18条接受规则断言，没有新增codec/math断言。

## 静态来源与重要行为

既有Rea Task.Start（0x180426750）证明首次state=1且未阻断时，先处理教程页55，再逐事件Evaluate/Execute，再HasRewardActions，最后写state=2并调用目标Start。既有Event.Execute（0x180421E30）是所有动作前钩子→集合Execute→所有动作后钩子。本轮Rea查询证实集合Execute（0x18046E380）按向量顺序调用+8槽。

原始PE只读vtable映射表证实教程表0x180796050和钱币表0x180796220的+0x18/+0x20槽均为0x180015880；本轮Rea汇编证实该函数只有RET，因而此域可完整处理事件钩子，没有丢弃未知回调。类型27由既有Factory和教程Execute/Read证据相互约束，页号保持原32位无符号解释。

**接受奖励后是追加任务UID，不是清空列表。** Task.Start汇编0x180426834读取任务+0xA8，放入本地变量，传给0x1800290D0，目标是所属quest+0x50。新Rea正文与汇编证实该辅助函数是uint向量追加，包括正常有效向量的自引用保护和扩容路径。本实现保留已有UID及重复UID；多个奖励动作每次Start只追加一次，不按动作个数追加。接受金额不调用完成奖励AdjustRewards；难度2用例仍只发原25。GiveMoney数值规则复用前期已恢复实现，包括金额0清空钱包。

## 输入、事务和适用范围

输入为任务UID匹配的解码on_accept向量、明确事件数量、条件指针状态、动作类型/版本、钱包与冷/热名字缓存、教程状态、明确的父quest UID索引。当前条件限于不被这两个动作改变的已有getter：等级、难度、硬核、玩家token、server token、anyone token。激活事件按动作原顺序执行；条件为假的事件可跳过未知动作；未知条件不当作false。

接受阶段奖励检测在执行后重新求值。钱币动作即使金额0仍是奖励；纯教程、空动作指针、未激活钱币事件不写奖励UID。已知完整UID索引中缺少父quest时，按原分支跳过该追加；索引未知或身份不一致则Unsupported。预检复制钱包及冷缓存、教程位图/列表/通知；同时预检全部目标Start钩子，故后续动作或父索引失败不会提前发钱、解锁、追加、激活任务或注册目标。正常首次接受只执行一次；活动任务再次Start与运行阻断分支不重复接受动作。

直接TaskMutations.Start/Lifecycle.Start的保守限制保持有效。IAcceptRuntime接口本身不证明任意实现等价，支持声明只覆盖审计的AcceptActions。未覆盖动作/版本、可能被动作改变或未恢复的条件、未知onAccept向量、非空原版教程UI订阅者仍Unsupported。正常有效内存、稳定上下文和成功分配是值语义边界，不模拟原分配器、故障指针、并发突变或原版UI。

## 验证和文件

18条边界断言覆盖首次与重复启动、阻断、动作顺序、多动作单次记录、重复UID、金额0、false条件跳过未知动作、难度金额不缩放、负页号经QST字段适配保留原位、未知版本/向量/条件、冷缓存及后续动作/目标/索引失败原子拒绝。先修复自有实现的引用遗漏与自制QST版本字段宽度，再由相关测试和最终统一构建通过，未改动官方格式或资源。
