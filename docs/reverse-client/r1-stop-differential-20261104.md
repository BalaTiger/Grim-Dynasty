# Owned Stop / exception comparison and deferred detach

Three new bounded observations completed on 2026-11-04 using the existing harmless fixture and the installed Rider command-line LLDB. A request made while the fixture was running was safely completed at its next exact owned breakpoint, followed by normal fixture exit. **Recovery from an unknown exception stop remains unproven and prohibited.** No original-game launch or attach occurred.

| Observation | Recorded evidence | Actual handling |
|---|---|---|
| Controlled Stop | One successful helper Stop; StopID 1 to 2. New thread `0x1fb4`, first-chance `0x80000003` at `ntdll+0x123f40`; PC is one byte later. Private stopped event has `interrupted=true`. | Unchanged candidate rejects reason 6 / `0xffffffffffffffff`. Helper Continue/Detach/Kill are all zero. Harness terminates only its identity-verified disposable fixture. |
| Fixture's own DebugBreak | No Stop call. Original main thread `0x39e8`, first-chance `0x80000003` at `KernelBase+0x113122`; stack includes `fixture+0x14c6`. Event has `interrupted=false`. | Same unknown-exception refusal; helper Continue/Detach/Kill all zero. No unexpected-continuation marker. Only the owned fixture is terminated for cleanup. |
| Deferred detach | Running request acknowledged before first GO; no Stop. Exact breakpoint 1.1 at fixture RVA `0x1020`, stable StopID 2, exactly one matching thread and no foreign stop. | Delete owned breakpoint once, Detach once; helper Stop/Continue/Kill zero. After LLDB exits, second GO produces `DONE late_count=3 result=42 debugger=0`, fixture exit 0. |

The first two exit-zero results are consequences of the harness's explicit `TerminateProcess(..., 0)` cleanup, as recorded by the actual backend; they are **not normal program completion or recovery successes**. The third case has independent fixture execution, debugger-absence and natural-exit evidence. Its `semantic_pass=false` field deliberately prevents interpreting this observer experiment as original-game semantics or gameplay acceptance. Its probe-level `own_cleanup_pending=true` describes the live detached fixture before the parent sends second GO; the later gate, Job and independent release receipts establish final cleanup.

The observed stack/thread/event differences distinguish these two controlled experiments. They do not establish a general exception classifier: both have reason 6, sentinel data and the same first-chance exception code. The installed backend log channel actually worked and supplied code, thread, chance and addresses. It did not supply a unique identity connecting an arbitrary Stop request to an exception. No concurrent Stop/self-exception race was tested. `interrupted=true`, a system-module address or a successful Stop alone must not permit automatic Continue/Detach. The earlier upstream review also shows a pending interrupt flag can mark a later natural stop; that is source analysis, not proof of this installed fork in every race. [LLVM 9 process event handling](https://github.com/llvm/llvm-project/blob/llvmorg-9.0.0/lldb/source/Target/Process.cpp#L3588).

The deferred path avoids calling Stop during running execution. It does not recover an already unknown stop, guarantee that another breakpoint will be reached, or prove a timeout can safely detach an arbitrary target. The test harness's kill-on-timeout and disposable-fixture cleanup are **not** a proposed original-game recovery policy. A future observation plan would still need explicit no-hit / foreign-stop handling and human handoff; this stage does not activate the candidate observer or schedule an original retry.
