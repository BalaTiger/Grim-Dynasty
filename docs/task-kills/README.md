# 击杀事件 → 条件计数 → 目标变化 → 自动完成

本批新增自有 `GrimDynasty.TaskKills.dll`，并扩展自有TaskAuto模块的条件生命周期接口。可重编译源码在 `src/task_kills/`；`build_kills.ps1`产出测试、官方参数接入与原创`KillQuestDemo.exe`。演示不读原版资源或DLL，不产生实际战斗、奖励、网络、Steam或存档操作。

## 已运行的整体链

Start注册事件11处理器→首帧目标未满足→解码后的击杀事件到达→计数与两变化字节更新→Task.Update清理变化/处理目标→达到阈值后自动完成空动作任务→结束钩子注销处理器→后续事件不再投递→Reset归零计数与目标状态→可再次接取。没有手工调用Complete来代替自动完成。

当前限制：完成事件/目标动作必须为空，0x2a订阅列表已知为空，dont_propagate阻止网络发送；文字提示时间门必须尚未打开，且纯/有效的临时本地化读取上下文被显式提供。显示时间门打开、未知订阅、奖励动作或网络依赖仍Unsupported，不吞掉未处理的dirty标志。

## 来源与分析缺口处理

Rea 6.5.0实际结果保存在rea/：四次读取/反汇编成功；第五次对`0x180470ed0`的反编译失败，原始错误完整保留。其含义是Ghidra未识别此叶函数，Rea将未解析VA回退为文件偏移后找不到映射，**不是已成功取得该函数伪代码**，也不是安装/目标路径错误。

随后使用本机已安装的同版本Ghidra 12.1.4，自写短Seed/Export Java脚本，在项目分析副本中按已验证虚表地址建立函数边界，取得ghidra-selected/functions.json及followup.json。它们明确标注直接Ghidra来源，不能称为Rea MCP成功输出。完整首次分析耗时188秒；后续复用已保存项目并`-noanalysis`，不反复全库分析。源码/入口脚本存tools/static_analysis/。原PE字节未被修改、未执行。

首次headless直接启动/点号路径尝试失败，日志已保留；成功使用官方analyzeHeadless入口。首次Ghidra加载器生成了用户目录的工具符号缓存，未改变系统设置；后续运行的APPDATA/LOCALAPPDATA按进程固定到项目analysis/selected-kill-runtime。没有清理或覆盖用户已有缓存。分析数据库和工具缓存为本地私有产物，其独立目录的.gitignore阻止意外纳入发布。

## 实际还原规则

| 函数/字段 | 已证实行为 |
|---|---|
| 配置读取 0x180470b10 | 路径逐字节将反斜杠改斜杠，其他字节经CRT tolower；目标数量存+0x38 |
| Evaluate 0x180470ed0 | 当前数量+0x3c与目标+0x38作**有符号32位**比较，六种选择器，实际当前值在左；非法选择器在本模块支持域外 |
| Start 0x180470f50 | 回调owner指针绑定自身，注册固定事件11；不归零计数 |
| End 0x180470f80 | 注销相同处理器身份，然后清空owner；不清计数/变化字节 |
| Reset 0x180470fb0 | 当前数量写0，+0x15写1；**不清+0x14** |
| 处理器跳板 0x1804713c0 | 从嵌入对象+0x10取owner，转到0x180471180，保留事件参数 |
| 事件处理 0x180471180 | 见下方RTTI、所有者、记录名规则；命中后32位加1，+0x14/+0x15均写1 |
| 本地化 0x180470fc0 | 传入有符号min(当前,目标)与目标，使用tagConditionHasKilled；本批未宣称完整格式化/渲染已恢复 |
| 目标OnChanged 0x180422450 | 清理dirty后的路径会检查每个条件+0x15，读取/格式化文字并调用显示钩子 |
| 显示钩子 0x180471080 | 只有有符号`delay < now-last`才调用ShowCinematicText并更新last；本批只执行门未打开的无显示分支 |

虚表来自实际Condition工厂case10：primary0x1807968e8、嵌入事件表0x1807968d0。slot0是析构，slot1才读配置；语义以函数体/调用点为准，不凭自动符号名称推断。

事件体中完整std::string位于+8，两个对象ID在+0x28/+0x2c。来源ID必须解析为Player，或解析为Monster且其虚表+0x8d0返回的ID解析为Player；并不限定主玩家。来源不满足时不读取目标记录名。目标对象若为Monster且其+0x20a4字节非零则忽略；其他已知类型/已知缺失对象通过该守卫。该字节的更具体领域名称未验证，模型保留中性命名。未知索引、RTTI或必要字段返回Unsupported，不能冒充“不存在”。

配置规范化与事件匹配不同：事件记录名**不归一化**，按完整长度/字节比较，区分大小写，嵌入NUL保留；配置列表多个匹配只加一次。计数不会在目标处饱和，保留32位回绕。路径规范化仅覆盖ASCII；大写输入要求显式已知C/ASCII小写映射，非ASCII CRT locale行为Unsupported。193个官方名称均在已覆盖域。

## Task.Update顺序修复与支持域

自动模块增加显式已证实条件提供者，保留主体控制流与开始/完成/重置钩子。恢复+0x14清理与+0x15文本变化路径，在不显示提示的域内继续推进。还保留一个反直觉分支：后面的“已满足且仍满足、但dirty”的目标会把Task.Update的全局返回标志清成false；前面已经发生的目标状态写入仍保留，但不发0x2a事件，也不因此完成任务。固定断言专门覆盖此顺序，未擅自修正原生行为。

提供者接口不是任意插件代码都可称为原版实现的许可；等价边界仅适用于这里实际证据支持的实现。已解码事件与对象索引是显式模拟输入，不是从真实角色/存档取得。文本显示打开时拒绝执行；纯本地化上下文声明不等于已恢复文字格式化或渲染。序列化槽虽有静态函数证据，但本批不实现或调用真实存档读写。
