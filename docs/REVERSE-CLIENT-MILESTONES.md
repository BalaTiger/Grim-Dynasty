## 目标与路线边界

- [RECOVERY-TARGET.md](RECOVERY-TARGET.md) 的最终目标仍是独立、行为等价、可重新编译的实现，保持原底层系统和玩法数值；不是 mod，不以调用原版 DLL 的宿主或反编译伪代码代替实现。
- [phase-1/PLAN.md](phase-1/PLAN.md) 规定明末包装、原创地图/任务/美术及本项目自己的新存档。二十八星宿仍是明确设计例外。R 系列先交付客户端最小可用子集，不等于长期内容全部完成。
- 本轮客户端方向明确包括鼠标选择、点击移动、寻路、输入、相机、场景资源和 UI；随后接真实攻击、敌人死亡、拾取、装备和 HUD。“真实”指客户端操作实际驱动完整状态变化，不能靠测试注入死亡事件、默认成功回调或猜测初始属性制造结果。
- 原创内容、平台适配和逆向所得行为分别标记。未知按键语义、资源格式、算法、数值与失败状态不能以表现相似代替证据。
- 原版安装保持只读，不接触玩家/Steam 云存档，不运行原游戏，不改系统安全设置，不 commit、push 或部署。Rea 的实际执行已进入 R0 授权范围；具体工具运行、构建或其他受控动作仍使用所需正式审批机制，不绕过拒绝、不擅装额外软件。原版动态对照须另有明确授权。

## 证据分层

| 层次 | 必须保留的证据 | 可证明范围与限制 |
|---|---|---|
| E0 工具实际可用 | 实际进程/连接、工具名称、请求、返回、时间、失败信息 | 证明本机确实执行指定动作。配置、安装文件、工具目录或模拟返回不能替代真实执行；工具成功不是功能完成。 |
| E1 原版静态事实与合同 | 输入 hash、精确函数/数据范围、原始输出、调用/字段对应、条件与未知项 | 支持所读范围内的规格。导出名、磁盘零值、局部 prefix 和伪代码不能推广为完整运行时合同。 |
| E2 自有实现与局部验证 | 源码 hash、构建日志、输入来源、实际测试结果、支持域/Unsupported | 证明自有代码在这些输入与前置条件下成立。fixture 通过不等于原版动态一致或游戏可操作。 |
| E3 客户端集成验收 | 实际客户端产物、资源来源、输入到状态到画面的链条、保存/重开结果、可见复现步骤 | 证明用户能操作限定范围内的同一客户端状态。切片可用不等于完整引擎、全内容或正式样本兼容。 |
| E4 原版动态对照（若另获授权） | 合法原版实际运行的成对输入/输出与隔离记录 | 只证明指定版本、指定条件下的动态一致性；未开展就写“未验”，不能用自有运行或静态推断冒充。 |

每项结论分别写出“原生证据”“自有实现”“实际验证”“仍缺部分”。已有模块只在覆盖当前输入和所有权条件时复用；改动影响旧接口才做必要回归，注明新增与复跑。累计断言数、读取字节数或函数数量不换算成项目完成百分比。

## R0：真正接通并使用 Rea

**范围与依赖：** 核对本机现有 Rea、实际启动/连接方式和已允许的分析后端，只处理已定位的项目/原版只读目标。建立真实工具链，再依直接引用选择 R1 最小入口；不恢复无边界函数覆盖。

**可见交付与验收：**

1. 提供实际 Rea 会话的工具调用及成功返回，注明版本、后端、输入文件 hash 和精确范围；配置文件、工具清单、模拟返回或未执行命令均不能替代。
2. 对一个已定位且与后续客户端路径有关的有限目标取得可复核输出，保存原始结果、地址及解释；原版输入前后 hash 一致。
3. 给出 R1 的最小证据入口与缺口。连接成功和分析成功分别记录；失败或不支持的能力保留原文。

**停点：** 未真实返回、后端能力不足、权限拒绝或需额外安装时，停止受影响动作并报告目标与原因；不能用其他工具冒充 Rea 已通过。范围内独立整理可继续。R0 通过后进入 R1。

**范围外：** 原游戏运行、全库自动扫描、新工具安装、安全策略变化、DRM/Steam 绕过；没有游戏功能验收。

## R1：鼠标可控的逆向客户端基础

**范围与依赖：** 依 R0 实际工具能力及已有资源解码，核对鼠标选择、屏幕到世界位置、点击移动命令、路径请求/结果、输入派发、相机、场景资源与最小 UI 的直接合同，接入可重新编译的客户端。旧自绘 WinForms/WASD 路线不再推进。

**可见交付与验收：**

1. 独立客户端打开实际场景，记录资源、空间/碰撞/导航数据及读取链的来源。原创替换资产明确标注；手写矩形背景不证明原场景资源链已恢复。
2. 用户能用鼠标选择角色/目标并点击可达地面移动；记录命中对象或世界坐标、移动命令、路径结果及角色位置变化。画面、相机和最小 UI 引用同一状态。
3. 固定样例包含直达点、障碍后可达点、不可达点和 UI 区域点击。依已证合同核验绕行、失败/停步及 UI 与世界输入分流；未知明确 Unsupported，不能用瞬移、穿墙或键盘代替完成。
4. 保存启动/操作步骤、输入和状态证据、截图或短录屏及源码/产物 hash。无窗口模型测试不能独自替代可见客户端验收。

**停点：** 资源、命中、导航或输入依赖未知时，保留明确边界，不发明原生算法或用原型演示宣布通过。阶段通过后通知用户并进入 R2，无需再次等待阶段许可。

**范围外：** 全世界/DLC、全部 UI、美术替换、复杂 AI、攻击结算；R1 不是战斗可玩验收。

## R2：攻击、死亡、拾取、装备与 HUD 闭环

**范围与依赖：** 在 R1 同一客户端中选最少的一名玩家、一种敌人和一个已核实装备/掉落输入，闭合属性初始化、攻击输入与目标、命中/伤害、生命变化、死亡生产、拾取及装备必需的直接路径。复用已证条件、库存、奖励和所有权模块，不另建展示用钱包或脱离会话的状态。

**可见交付与验收：**

1. 鼠标攻击实际驱动攻击与命中链；敌人生命来自已核实数据和初始化规则。HUD 显示同一对象的实际生命、目标与必要状态。
2. 实际结算触发敌人死亡，并由该生产链产生死亡/击杀事实；重复通知不得重复收益。内部 fixture death 桥可复用消费者，不算生产链完成。
3. 已核实的掉落/物品创建进入场景，拾取进入同一库存；装备通过实际资格、槽位与状态更新，显示与权威状态一致。不得用虚构掉落、武器子类、价格或默认成功回调跨过未知。
4. 固定样例包含正常流程、无效/失效目标、重复死亡/拾取、装备条件不符、途中保存后退出重开。失败前缀、物品身份、奖励一次性及重开状态必须可解释。

**停点：** 缺少真实初始生命、伤害绑定、死亡生产、掉落或装备合同就保留缺口，不开放“模拟攻击成功”入口。R2 通过后通知用户并进入 R3。

**范围外：** 全职业/技能、全怪物生态、全商店经济、任意官方任务、联机和原存档兼容；不能为本轮验收无限扩链。

## R3：初步可用版本验收，然后立即停止

**范围与依赖：** 将 R1/R2 已通过路径组成一条短而完整、可重复操作的客户端路线，不新增一批底层恢复任务。以可用性和恢复性验收，不以运行时长或断言数代替体验。

**可见交付与验收：**

1. 从独立入口新建本项目角色，进入场景，鼠标移动/选择/攻击，击败敌人，拾取并装备物品；HUD 与真实状态一致。
2. 行动中途和完成后分别保存、退出、重开并继续；不重复发放已消费收益，不丢失物品/装备及角色归属。损坏或不支持的自有状态明确报错并提供已验证恢复办法，不静默创建默认角色。
3. 交付可运行产物、可重现构建/操作说明、资源来源、实际结果及不支持功能清单；区分静态/自有验证与原版动态对照，不称完整替代或全样本兼容。
4. 向用户报告“初步可用”验收结果和操作方式。不得擅自自动打开前台窗口；可见验收沿用当前明确的展示/执行授权。

**最终停点：R3 达到初步可用后立即停止自动推进。** 不自行创建 R4，不顺势扩地图、职业、交易、DLC、联机或全引擎恢复。未通过则仅处理本轮验收具体阻塞并报告证据；完成后交回用户决定下一阶段。

**范围外：** 完整替代 Grim Dawn、发布、原存档迁移、全量平衡/性能承诺和全部长期明末内容。没有依据的总工期及完成百分比不写入计划。
